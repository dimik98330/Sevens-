# C-frontend — «Идеи для региона» (владелец: агент C, ветка `agent/c-frontend`)

Понятный адаптивный поток по `docs/05_UX_UI_DESIGN.md` на контрактах `docs/03_DATA_API_CONTRACTS.md`:
регистрация/вход → мастер идеи (3 шага) + файл → «Мои идеи» → карточка с таймлайном →
уведомления → очередь сотрудника с фильтрами → карточка обработки (назначение, статус,
публичный ответ vs внутренняя заметка) → минимальный admin-reroute. Плюс объяснение
автоматического маршрута («Почему это направление?»), демо-баннер, `loading/empty/error`,
`401/403/404/409`, мобильная вёрстка 360–390px, клавиатура и доступность.

## Запуск

```bash
node server.mjs --port 5173
# http://localhost:5173/
```

Тесты (ноль зависимостей):

```bash
node --test frontend/tests/routing.test.js frontend/tests/contracts.test.js
```

## Режимы данных

- **По умолчанию — демо-mock по контракту в браузере** (`js/lib/mock.js`, `?mock=1`).
  Используется только для разработки/тестов, пока API B не готов (B-01 IN_PROGRESS на момент C-01).
  Mock реализует те же DTO/коды ошибок 03: `expectedVersion`, `Idempotency-Key`, 409/401/403/404/413/415.
- **Настоящий backend B:** открыть `http://localhost:5173/?api=https://backend-host`
  или выставить режим на экране `#/settings`. Mock при этом полностью обходится —
  все запросы идут в `/api/v1` настоящего backend. Перед выпуском флаг mock удаляется
  из production-сценария (проверка приёмки 03 §9).

Согласование DTO с B — сообщением `CONTRACT` в журнале (`docs/tools/team_bus.py`).

## Что где

- `index.html`, `styles.css` — токены 05 (светлый фон, один акцент `#176B5B`, 16px, радиусы 16/10).
- `js/lib/contracts.js` — enum/лимиты/переходы/ошибки из 03 (UI показывает только допустимые переходы).
- `js/lib/routing.js` — правила `rules-v1` из 04 (чистая функция + объяснения; проценты не показываем).
- `js/lib/api.js` — один typed API-клиент: `Idempotency-Key` на каждое намерение, повтор — тем же ключом.
- `js/views/` — экраны; `js/components.js` — статусы (цвет+текст+пиктограмма), таймлайн-лента, скелетоны.
- Переключателя KK нет сознательно: полного перевода нет (05 §13).

## Проверенные состояния

skeleton → empty (два разных: пустая очередь vs пустой фильтр) → error+retry →
`NEEDS_INFO` с подписью «Нужен ваш ответ» → конфликт версии с сохранением текста →
терминальные статусы без переходов → `ANSWER_PROVIDED` без слов «проект реализован».
