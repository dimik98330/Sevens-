# Классификатор идей — реализация и проверка 30.09.2026

Задача: готовая модель, понимающая русский, казахский и смешанный текст;
надёжная маршрутизация идеи по действующему серверному справочнику.
Выбор пользователя: Vercel, классификация через внешний API.
Ветка `codex/sevens-experience`, базовый HEAD `d66d2b1`; проверки относятся
к незакоммиченному рабочему дереву. Изменения фронтенд-чата сохранены.

## Что реализовано

- GPT-6 Sol через Responses API со строгой JSON-схемой. Модель определяет
  тему, дополнительные темы, цифровую составляющую и необходимость проверки.
  Статусы, ответственных и организацию она не выбирает: это делает сервер.
- Вход содержит только название, проблему и решение. Поля контактов,
  координаты, файлы, данные профиля и сессии не отправляются. Телефоны и
  email в тексте скрываются простыми шаблонами; это не полная анонимизация
  произвольного свободного текста. `store:false`; ключ остаётся на сервере.
- Ответ проверяется Zod, допустимыми категориями и точными цитатами из
  входа. Посторонние поля, выдуманные цитаты, отказ модели и неполный ответ
  дают резервный результат. Цитата подтверждает источник, а не истинность
  выбранной темы.
- `rules-v2` учитывает контекст: отказ от вмешательства, отсутствие объекта,
  неисправность, фон, противопоставление и несколько целей. Его конечный
  словарь и простые правила не понимают любой произвольный текст.
- Противоречие с уверенными правилами, исключённая тема, неясные отрицания,
  несколько равноправных целей и граница ЖКХ/экологии направляются в TRIAGE.
  Выбор автора хранится отдельно от подсказки. Сотрудник может уточнить маршрут
  с обязательной причиной.
- Предпросмотр работает через `POST /api/v1/ideas/routing-preview` по
  актуальному каталогу. Он не создаёт заявку. Форма сохраняет текст при
  ошибке подсказки; ответ устаревшего запроса игнорируется.
- Анализ вне SQL-транзакции; результат привязан хешем к актуальному тексту
  заблокированной идеи. Preview и submit переиспользуют результат в пределах
  процесса. Официальное решение и внутренний анализ сохраняются атомарно.
- Общий бюджет в PostgreSQL: 100 новых платных вызовов в час, 50 на аккаунт.
  Независимые процессы используют одинаковые блокировки. Доступный кеш
  не расходует новый бюджет. Отказ одному аккаунту не кешируется для другого.
  Время ожидания бюджета включено в общий deadline. После исчерпания бюджета
  работают правила. Это начальные технические ограничения, не гарантия суммы
  расходов: установите отдельный лимит бюджета проекта у провайдера.
- Сетевой запрос модели ограничен 8 секундами, общий путь — 11 секундами.
  Кеш ограничен 256 записями/5 минутами, одновременно до двух вызовов на
  процесс. Между serverless instances кеш не общий; бюджет общий.
- Локальная MiniLM была проверена как эксперимент и оказалась слабее:
  совпадение темы 55/90. Локальная ML-зависимость исключена из production;
  экспериментальные файлы и скачанные веса оставлены только в игнорируемом
  локальном `.data`, сервер их не загружает.

## Измеренный результат

Замороженная выборка `fixtures/routing-v2-validation.json`: 90 синтетических
случаев, 30 RU / 30 KK / 30 смешанных; 29 групп сценариев. Три случая —
известные регрессии. Это не 90 независимых реальных обращений и не полевая
оценка; проверки носителем казахского языка не было. Gold не менялся.

| Метрика гибридного pipeline | Результат |
|---|---:|
| Совпадение выявленной темы | 89/90 |
| Допустимая категория и политика маршрутизации | 90/90 |
| Автоматически распределено | 69/90 |
| Ошибочные автоматические назначения | 0/69 |
| Передано специалисту | 21/90 |
| Обязательный ручной разбор, ошибочно назначенный автоматически | 0/18 |

По языкам: RU 30/30, KK 29/30, смешанные 30/30. Модель ошиблась в теме
казахского обращения о сборе мусора; спорная граница ЖКХ/экологии отправлена
специалисту. Один ответ обработан правилами при недоступности модели.
Нулевая ошибка среди 69 назначений не доказывает отсутствие будущих ошибок.

Исходный live-прогон: P50 2788 мс, P95 3821 мс. Финальная проверка повторно
применила текущие защитные правила к сохранённым ответам без платных вызовов.
Нулевая задержка такого пересчёта — скорость кеша, не скорость API.

  LLM preview → submit → сохранённая карточка; 6 checks PASS.

  доступа и перезапуска был проверен в отдельном backend release-аудите.

## Включение

Только на сервере:

```dotenv
CLASSIFIER_MODE=llm
OPENAI_CLASSIFIER_MODEL=gpt-6-sol
OPENAI_API_KEY=<secret configured in hosting environment>
ROUTING_CLASSIFIER_VERSION=rules-v2
```

Применить миграции 0005 и 0006 вместе с предыдущими. Перезапустить API после
изменения окружения. `CLASSIFIER_MODE=rules` отключает платные вызовы.
Не добавлять ключу префикс `NEXT_PUBLIC_`. В `.env.sevens` режим уже настроен;
основной API 18081 перезапущен, readiness PASS, все шесть миграций применены.
Next 3100 и PostgreSQL 5436 сохранены; demo seed не запускался. Будущие
изменения окружения требуют перезапуска API.

`node scripts/evaluate-semantic-live.mjs` пересчитывает только полный кеш.
Новые ограниченные платные вызовы разрешает явный флаг `--live`; в этом
запуске он не требуется. Для полного deployment на Vercel остаются отдельные
инфраструктурные изменения: [перечень](VERCEL_DEPLOYMENT_GAPS_2026-09-30.md).

Источники API: [GPT-6 Sol](https://developers.openai.com/api/docs/models/gpt-6-sol),
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
